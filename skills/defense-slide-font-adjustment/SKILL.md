# Defense Slide Font Adjustment

Use this skill when changing font sizes or local layout in the user's thesis defense slides.

## Core Rules

- Do not change slide titles (`h2`) unless the user explicitly asks to adjust titles.
- Do not change the bottom footer text generated by `.slide::after` / `data-footer` unless explicitly requested.
- Do not change the bottom-right `.slide-number` unless explicitly requested.
- Apply font changes with slide-scoped selectors such as `#slide-3 ...` so other pages are not affected.
- Preserve the existing blue-white academic style, card structure, spacing logic, and evidence-image treatment.
- Page references from the user should be interpreted by the visible bottom-right page number. If visible page numbers are duplicated or skipped, identify the slide by both visible number and section title before editing.

## User Preferences Captured

- When the user asks to adjust font size, default to adjusting body/card/label/caption/table text only; leave page title, footer, and page number unchanged.
- The user often asks for "black text" to be larger. Treat this as dark body text, card descriptions, chart labels, table text, and explanatory notes, not blue section titles unless clearly intended.
- Do not allow text to touch or overlap card borders. Maintain visible top/bottom padding after every font increase.
- Do not allow one UI block to overlap another. If text grows, adjust grid rows, gaps, card padding, line-height, or neighboring image/table sizes.
- If text is "too large" or makes the page messy, reduce it to a moderate size and restore stable spacing rather than preserving the requested multiplier mechanically.
- For short paired phrases separated by a comma in route/step cards, the preferred treatment is a manual line break after the comma, e.g. first clause on line one and second clause on line two.
- For images inside evidence cards, keep the image complete with `object-fit: contain`. If the user asks to enlarge an image within its border, increase `max-height`/`width` inside the existing frame rather than cropping.
- For dense tables, prioritize readable layout and non-overlap over exact font multipliers. It is acceptable to use a smaller increase, widen the table, make it span a row, reduce cell padding, or move the caption above the table.
- For chart/table pages, keep chart rows, table captions, and summary cards separated with explicit grid rows/gaps. Avoid letting chart labels touch table captions.
- For metric cards such as EER/FAR/FRR explanations, allocate enough vertical height for formula notes; do not let footers cover explanatory boxes.

## Practical Workflow

1. Locate the target slide by visible page number and confirm the section title.
2. Identify exactly which text should change: card headings, labels, captions, bullets, chart labels, table cells, body notes, or black/dark text.
3. Add or adjust slide-scoped selectors only. Prefer local overrides over global class changes.
4. When increasing fonts, check the layout budget at the same time:
   - card `padding`
   - grid `rows` / `columns`
   - `gap`
   - `line-height`
   - image/table `max-height`
   - `overflow`
5. If content approaches a border, increase internal padding or reduce font size slightly. Do not leave text touching top/bottom card borders.
6. If a table or figure becomes messy after font changes, re-layout the surrounding area first, then tune font size.
7. Run static checks when possible:
   - slide count remains unchanged
   - CSS diff is slide-scoped
   - no accidental `h2`, `.slide::after`, or `.slide-number` edits
   - no obvious overlap-prone changes such as enlarged text without added spacing
